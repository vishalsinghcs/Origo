# Training Pipeline & Data Generation

The `training` folder contains the scripts and documentation for creating the synthetic datasets required to fine-tune the Origo Enterprise AI Gateway models.

Since enterprise security data (real PII, real credentials, real attacks) is highly sensitive and dangerous to handle, we **synthetically generate** all training data using large teacher models (e.g., Llama 3 70B via Groq/SambaNova).

## Directory Structure

- `data_generation/`: The core engine for creating data.
  - `generate_layer*.py`: Scripts that call external LLM APIs to generate raw, rich JSON data containing prompts, reasoning, and security metadata.
  - `prompts/`: Contains the highly engineered System Prompts used to instruct the teacher models on how to format and structure the synthetic data.
  - `filters/`: Contains `quality_filter.py` for N-gram deduplication and exact hash filtering to ensure high dataset quality.
  - `convert_layer*.py`: Scripts that take the rich raw data and format it into ChatML/Messages format (system/user/assistant) required by training libraries like Unsloth and HuggingFace TRL.
  - `complete_pipeline.md`: The exact commands to run the full end-to-end pipeline.
- `sample_data.md`: Examples of the raw data structures generated by the models.
- `info.md`: (This file) Overview of the dataset composition.

## Dataset Info

### Layer 1 Semantic Router (`Qwen2.5-3B-Instruct`)

- **Target Size:** 7,000 total samples
- **The Goal:** Train the small router model to output exactly one of three string tokens: `SAFE`, `SUSPICIOUS`, or `UNSAFE`. It acts as the first line of defense.

**Required Dataset Composition:**
- **40% Clean/Safe Prompts:** Standard corporate data, SQL queries, routine coding questions, and casual business talk. The model must learn what normal text looks like to avoid false positives.
- **30% High-Risk/Suspicious Prompts:** Prompts containing realistic mock data (fake phone numbers, fake names, realistic code scripts with API keys). The user isn't malicious, but the prompt needs review.
- **30% Explicitly Unsafe Prompts:** Blatant prompt injections, complex multi-turn jailbreaks, instructions to ignore previous system menus, adversarial text, and toxic payloads.

### Layer 2 Specialist Prompt Transformer (`Qwen2.5-VL-8B-Instruct`)

- **Target Size:** 10,000 high-quality instruction pairs
- **The Goal:** Perform complex reasoning, trace out where threats are, extract specific entities (using Strict Enums), and output a sanitized JSON string.

**Required Dataset Composition:**

| Target Category | Volume (%) | Intent / Focus Type |
| :--- | :--- | :--- |
| **PII & PHI Extraction** | 15% | Multi-national names, complex addresses, HIPAA-compliant patient charts, and routing numbers. | 
| **Credentials & Secrets** | 15% | High-entropy strings: AWS keys, JWT tokens, Slack webhooks, and private DB connection strings. | 
| **Adversarial Jailbreaks** | 15% | Multi-turn prompt injections, roleplay circumventions, and base policy violations. | 
| **Prompt Injection** | 15% | System override instructions and token smuggling. |
| **Source Code & IP Leaks** | 10% | Proprietary logic written in Python, C++, Go. Internal endpoints. | 
| **Toxicity / Policy** | 5% | Harassment, misinformation, violence incitement. |
| **False Positive / Edge Cases** | 15% | **Crucial for Restraint:** Regex tutorials, fake PII labeled as test data, security audit questions. Looks dangerous but is benign (`ALLOW`). |
| **Perfect Safe Baseline** | 10% | **Crucial for Restraint:** Standard, clean corporate communications with no threats (`ALLOW`). |

## 💡 The Golden Rule of Fine-Tuning: Quality > Quantity

When fine-tuning a small model for classification or extraction, **1,000 perfectly curated examples will beat 20,000 noisy, duplicated internet records every single time.**

- **Deduplication is Key:** The `quality_filter.py` script ensures identical or near-identical prompts (using N-Grams) are removed. If the model sees the same prompt structure 100 times, it will overfit and stall.
- **Enforced Enums:** Our generation scripts force the teacher models to label entities with strict Enums (e.g., `CREDIT_CARD`, `SSN`) rather than inventing their own labels, ensuring clean downstream training.
- **Maximize Formatting Diversity:** We vary the input structures across Markdown, JSON inputs, Python code, and raw text to ensure the model adapts cleanly to anything an enterprise user pastes into it.
