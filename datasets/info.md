# Origo Datasets: Documentation & Analysis Guide

This document serves as the central directory and knowledge base for the Origo synthetic datasets. It outlines the dataset pipeline, folder structures, and the tools used to analyze and visualize the generated security data.

---

## 1. Dataset Lifecycle & Folder Structure

The dataset generation for Origo moves through three strict phases, stored in their respective directories:

### `datasets/raw/`
This folder contains the raw, unfiltered synthetic data exactly as it was generated by the "teacher" LLMs (Groq). 
- **`layer1/`**: Contains chunked `.jsonl` files (`part_000n.jsonl`) generated by `generate_layer1.py`. This dataset maps user prompts to a strict `SAFE`, `SUSPICIOUS`, or `UNSAFE` classification label.
- **`layer2/`**: Contains chunked `.jsonl` files generated by `generate_layer2.py`. This dataset is highly complex, mapping suspicious/unsafe prompts to exact security actions (`REWRITE`, `REDACT`, `BLOCK`, `ALLOW`), extracting entities (PII, credentials), and generating sanitized prompts.

### `datasets/filtered/`
This folder contains the **merged and cleaned** master datasets.
- Created by running `filters/quality_filter.py`.
- The filter scripts iterate over the `raw/` chunks, automatically reject duplicates (via exact and N-gram fuzzy hashing), drop malformed JSONs, remove hallucinations (like broken `openai/gpt-oss-120b` samples), and combine them into a single, high-quality `layer1.jsonl` or `layer2.jsonl` file.

### `datasets/processed/`
This folder contains the final, training-ready datasets.
- Created by running `convert_layer1.py` and `convert_layer2.py`.
- The JSON objects are flattened and transformed into the conversational `ChatML` format required for Unsloth / HuggingFace fine-tuning.

## 2. Dataset Analysis & Visualization

To ensure the synthetic data meets enterprise quality standards, we utilize powerful visualization and analysis tools located in the `datasets/analysis/` folder.

### 2.1 The Streamlit Dashboard (`visualize_layer1.py`)
A custom, interactive web application built with Streamlit.
- **Purpose**: Deep, interactive visualization of the dataset directly in your browser.
- **Features**: 
  - Pie charts and bar graphs for `SAFE/SUSPICIOUS/UNSAFE` distribution.
  - Tracking of which Teacher Models generated the data.
  - A dynamic "Data Explorer" to filter prompts by category and read the raw text alongside the model's reasoning.
- **Usage**: Run `streamlit run visualize_layer1.py` from the `analysis/` folder.

### 2.2 Automated Reporting (`raw/analysis.py`)
A heavy-duty python script designed for deep exploratory data analysis (EDA).
- **Purpose**: Batch-analyzes the entire dataset and generates static HTML dashboards and a comprehensive Markdown report.
- **Outputs**:
  - `reports/dataset_report.md`: A highly detailed text summary showing exact token lengths, confidence intervals, top entity types, and raw examples.
  - `layer1_dashboard.html` / `layer2_dashboard.html`: Fully offline, interactive Plotly charts (heatmaps, box plots, word clouds) that can be opened in any browser without running a server.
