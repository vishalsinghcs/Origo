# Origo Datasets: Documentation & Analysis Guide

This document serves as the central directory and knowledge base for the Origo synthetic datasets. It outlines the dataset pipeline, folder structures, and the tools used to analyze and visualize the generated security data.

---

## 1. Dataset Lifecycle & Folder Structure

The dataset generation for Origo moves through four strict phases, stored in their respective directories:

### `datasets/raw/`
This folder contains the raw, unfiltered synthetic data exactly as it was generated by the "teacher" LLMs (Groq). 
- **`layer1/`**: Contains chunked `.jsonl` files (`part_000n.jsonl`) generated by `generate_layer1.py`. This dataset maps user prompts to a strict `SAFE`, `SUSPICIOUS`, or `UNSAFE` classification label.
- **`layer2/`**: Contains chunked `.jsonl` files generated by `generate_layer2.py`. This dataset is highly complex, mapping suspicious/unsafe prompts to exact security actions (`REWRITE`, `REDACT`, `BLOCK`, `ALLOW`), extracting entities (PII, credentials), and generating sanitized prompts.

### `datasets/filtered/`
This folder contains the **merged and deduplicated** master datasets.
- Created by running `filters/quality_filter.py`.
- The filter scripts iterate over the `raw/` chunks, automatically reject duplicates (via exact and N-gram fuzzy hashing), drop malformed JSONs, remove hallucinations (like broken `openai/gpt-oss-120b` samples), and combine them into a single, high-quality `layer1.jsonl` or `layer2.jsonl` file.

### `datasets/preprocessed/`
This folder contains the **pristine, manually cleaned** datasets ready for conversion.
- Created via deep data cleaning using Jupyter Notebooks (`preprocess_layer1.ipynb`, `preprocess_layer2.ipynb`).
- **Why we need this step**: Teacher LLMs occasionally hallucinate (e.g., outputting raw Markdown, Regex, or JSON inside the `rewritten_prompt` field, or guessing invalid `action` states). We use Pandas to write strict boolean masks to purge these edge cases, ensuring absolutely zero "toxic" formatting leaks into the final fine-tuning data.

### `datasets/formatted/`
This folder contains the final, training-ready datasets formatted for ChatML.
- Created by running `convert_layer1.py` and `convert_layer2.py` on the preprocessed datasets.
- The JSON objects are transformed into the conversational `ChatML` format required for Unsloth / HuggingFace fine-tuning. 
- **Strict JSON Output**: The assistant's responses are explicitly formatted as strict JSON blocks (rather than plaintext) to ensure the trained models output parseable data for the Layer 3 Policy Engine.
- *Note: We intentionally drop noisy classifications like `policy_violated` during this phase so the 8B models can focus 100% of their attention on reasoning and redaction, delegating strict policy matching to the backend.*

## 2. Dataset Analysis & Visualization

To ensure the synthetic data meets enterprise quality standards, we utilize powerful visualization and data wrangling tools located in the `datasets/analysis/` folder.

### 2.1 The Streamlit Dashboards
Custom, interactive web applications built with Streamlit. Usage: `streamlit run visualize_layerX.py`.

**`visualize_layer1.py`**
- Pie charts and bar graphs for `SAFE/SUSPICIOUS/UNSAFE` distribution.
- Tracks Teacher Model usage.
- A dynamic "Data Explorer" to filter prompts by category and read the raw text alongside the model's reasoning.

**`visualize_layer2.py`**
- Advanced mapping tailored to the Specialist Rewriter.
- **Action & Severity Distributions**: Plots `ALLOW` vs `REDACT` vs `BLOCK` vs `REWRITE`.
- **Threat vs Action Heatmaps**: Instantly visualizes exactly which threat types trigger which specific actions.
- **Entity Parsing**: Automatically unpacks nested JSON `entities_detected` arrays to rank top entities (e.g., `API_KEY`, `PASSPORT_NUMBER`).

### 2.2 Jupyter Preprocessing (`.ipynb`)
For granular dataset manipulation, we use Pandas in Jupyter Notebooks.
- **Purpose**: Rapid exploratory data analysis (EDA), locating missing values, fixing type casting errors (e.g., hallucinated dicts in string arrays), and exporting cleaned CSVs/JSONLs.
- **Techniques Used**: Advanced Boolean Masking, `.isin()` filtering, and `.str.get()` extraction on nested JSON columns.

### 2.3 Automated Reporting (`raw/analysis.py`)
A heavy-duty python script designed for deep exploratory data analysis (EDA).
- **Purpose**: Batch-analyzes the entire raw dataset and generates static HTML dashboards and a comprehensive Markdown report.
- **Outputs**:
  - `reports/dataset_report.md`: A highly detailed text summary showing exact token lengths, confidence intervals, top entity types, and raw examples.
  - `layer1_dashboard.html` / `layer2_dashboard.html`: Fully offline, interactive Plotly charts (heatmaps, box plots, word clouds) that can be opened in any browser without running a server.
